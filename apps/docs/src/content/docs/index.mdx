Loxep is an open-source, self-hosted application for observing marketplace activity and operating the commercial work that follows from it. The initial vertical slice is eBay monitoring and historical intelligence, built on a foundation intended to grow into commerce, inventory, projects and services, billing, accounting, tax support, documents, and reporting without turning into disconnected tools.

This site is the project specification as well as the public documentation. During foundation work, it should answer the questions a contributor or coding agent would otherwise have to guess.

## Current repository state

The web application is no longer a blank planned scaffold. The Kiranism TanStack Start dashboard has been adopted as a UI donor and moved into a Loxep workspace-aware shell with eight configured workspaces:

```text
/dashboard/*        cross-domain overview
/market/*           marketplace observation and opportunities
/inventory/*        stock, acquisitions, and movements
/commerce/*         catalog, listings, and orders
/finance/*          expenses, books, journal, and reporting
/infrastructure/*   domains, DNS, mail, fleet, and provisioning
/settings/*         installation administration
/starter/*          preserved donor/demo reference
```

The sidebar and command palette derive their navigation from the active workspace. Major product areas are peers of `/dashboard`, not children of one giant `/dashboard/*` navigation tree. The commerce ingestion path currently supports eBay, WooCommerce, and Medusa; the integration catalog contains 14 provider adapters at differing levels of implementation and live verification. Consult [Integration Status](./product/integrations-status/) rather than inferring support from the presence of a package or catalog card.

The default runtime direction remains deliberately small:

```text
loxep                    # TanStack Start + Graphile Worker
postgres-timescale       # PostgreSQL + TimescaleDB
rustfs                   # optional S3-compatible companion
```

One Loxep image supports `LOXEP_MODE=all|web|worker`. Local media storage remains the zero-extra-service default; generic S3 storage is supported when shared object storage is desired.

## Documentation rule

Starlight currently renders each page's frontmatter `title` as the page heading. New documentation pages should therefore **not** repeat the title as a Markdown `# H1`. Use `##` as the first content heading.

The docs content should remain portable. Astro/Starlight is the current renderer, not a permanent product dependency; migration to another documentation stack later is explicitly acceptable.
